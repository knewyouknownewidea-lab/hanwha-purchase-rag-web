배포 연결 게이트웨이
====================

기존 백엔드(8000)와 Ollama(11434)는 로컬에 둡니다.
이 게이트웨이(8010)는 비밀 토큰을 확인한 요청만 받습니다.
외부 화면의 서버가 이 토큰을 보관해야 합니다. 브라우저 JavaScript에 넣지 마세요.
현재 파일 생성만으로 외부 주소가 생기지는 않습니다. 별도의 인증 연결이 필요합니다.

시작
----
먼저 기존 백엔드와 Ollama를 실행합니다.
VS Code에서 outputs 폴더를 연 PowerShell 터미널에서 실행합니다.
토큰은 배포 담당자가 별도로 전달한 충분히 긴 비밀 값을 사용합니다.
아래 명령은 숨김 입력을 사용하므로 토큰이 명령 기록에 남지 않습니다.

::

    $secret = Read-Host '게이트웨이 비밀 토큰' -AsSecureString
    $pointer = [Runtime.InteropServices.Marshal]::SecureStringToBSTR($secret)
    try { $env:RAG_GATEWAY_TOKEN = [Runtime.InteropServices.Marshal]::PtrToStringBSTR($pointer) }
    finally { [Runtime.InteropServices.Marshal]::ZeroFreeBSTR($pointer) }
    & '..\work\chunking-venv\Scripts\python.exe' -m deployment

주소: http://127.0.0.1:8010
종료: 실행한 터미널에서 Ctrl+C. 이후 Remove-Item Env:RAG_GATEWAY_TOKEN
토큰은 32자 이상이어야 하며 소스/설정 파일/Git에 저장하지 않습니다.
게이트웨이는 단일 프로세스로 실행합니다. workers를 늘리지 마세요.

노출하는 경로
--------------
모든 경로는 Authorization: Bearer <비밀 토큰> 헤더가 필요합니다.

GET /health: 기존 백엔드 상태 확인
GET /models: 생성 모델 3개의 설치 여부
POST /jobs: 질문 작업 시작. 202와 job_id 반환
GET /jobs/{job_id}: running/succeeded/failed 상태 조회

POST /jobs의 JSON은 기존 POST /answer와 같습니다.
question, model은 필수이고 top_k 및 조회 ID/문서 종류는 선택입니다.
완료 응답의 result가 기존 백엔드 답변/출처 객체입니다.
모델은 qwen3:8b, gemma3:4b, llama3.1:8b만 허용합니다.

한 번에 질문 하나만 처리합니다. 사용 중에는 429와 Retry-After: 5를 반환합니다.
완료 작업은 15분 동안 최대 100개 보관합니다. 서버 재시작 시 작업 기록은 사라집니다.
폴링 간격은 2~3초를 권장합니다. 완료 후 폴링을 중단합니다.
요청 본문은 실제 수신 바이트 기준 8192바이트까지 허용합니다.
/index, /search, /prepare-prompt, /docs, Ollama API 등은 전달하지 않습니다.

검증
----
outputs 폴더에서 다음 명령을 실행합니다. 실제 모델이나 DB는 호출하지 않습니다.

::

    & '..\work\chunking-venv\Scripts\python.exe' -m unittest deployment.test_gateway -v

운영 범위
----------
이 PC를 켜고 백엔드·Ollama·게이트웨이와 연결 프로그램을 실행해야 답변할 수 있습니다.
공개 화면 서버의 이용자 인증/사용량 제한은 별도 구성 대상입니다.
이 토큰은 서버 간 인증용이며, 사용자별 로그인과는 다릅니다.
기존 생성 프롬프트, BGE-M3, Chroma 경로, 검색 기준은 변경하지 않습니다.
